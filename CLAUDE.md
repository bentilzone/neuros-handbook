# CLAUDE.md — neuros-handbook

The Neuros Handbook. Read [`AGENTS.md`](./AGENTS.md), then [`docs/_README.md`](./docs/_README.md).

## What this is

A Docusaurus 3 site in three passes:
1. a glossary of every term;
2. every feature end to end;
3. a page-by-page guide for each persona: supplier (`supply`), distributor (`distribution`), reseller/buyer (`purchasing`) and the platform operator.

Its screenshots and videos are captured from the real app, so the handbook shows what the code does.

## Structure

```
docusaurus.config.ts   url/baseUrl from HANDBOOK_URL / HANDBOOK_BASE_URL (Pages now, Amplify later)
docs/00-start …        sections; the numeric prefix is the sidebar order; index.md carries the slug
docs/_partials/        each guide page's body, written once: <Offers who="supplier" />. Shots are
                       `${props.who}/…`; links to sibling pages are <PageLink who page>
                       settings-personal.mdx is your own Settings tabs, shared by settings.mdx and the operator
docs/_README.md         authoring guide (the underscore keeps it off the site, dev builds included)
docs/30-api/           the API guide (hand-written) and reference/ (GENERATED by tools/api-reference.mjs)
sidebars.ts            one sidebar per navbar tab: Overview, Guides, API, Reference
src/theme/Navbar/Content  the two-row navbar (brand · search · links, then the tabs)
src/components/ThemeMenu  System / Light / Dark
src/components/        Shot (annotated screenshot + legend), FieldTable, Video, PersonaBadge
src/theme/MDXComponents.tsx  those components in every page without an import
src/data/shots.json    GENERATED by capture: shot id → file, size, numbered callouts
static/shots, static/video   GENERATED by capture
capture/stack.ts       throwaway Neuros: in-memory replica set, prepare-db (indexes first), every seed, engine, client build
capture/personas.ts    who each guide is shot as (seeded demo logins) and the real sign-in; `visitor` never
                       signs in (the public pages in 00-start/signing-in); the operator
                       signs in with two-step verification, enrolled per run by stack.ts (capture/totp.ts)
capture/walk.ts        the page-by-page walk every persona guide is shot from; a persona keeps the
                       sections its capabilities give it (sell, buy, stock) and names its demo records
capture/scenarios/     one file per persona: walk({...}) plus any extra shots and videos; operator.ts is its
                       own list (the console shares no pages with a company). Its waiting work comes from
                       the engine's seed:platform
capture/browser.ts     Chromium in Playwright's Docker image (linux/amd64, the package's exact version) for
                       laptops and CI alike; the page's localhost is tunnelled to the host stack
capture/callouts.ts    numbered arrows drawn on the live page before the screenshot
capture/run.ts         `yarn capture [--persona x] [--only id-prefix] [--app url]`; report in capture/.out;
                       drops manifest entries (and images) whose scenario is gone
.github/workflows/capture.yml  re-shoots on app merges (repository_dispatch app-changed) and weekly; opens a PR
tools/lint-public.mjs  refuses anything unpublishable
handbook.manifest.json every neuros-client route → the docs/ pages for it; the client's coverage test reads a
                       synced copy; tools/check-manifest.mjs (yarn verify) checks each page exists
.github/workflows/pages.yml  verify on PRs, deploy main to GitHub Pages
amplify.yml            the same build for Amplify, unused until the AWS move
```

## Must not

- **Must not** add or edit a screenshot by hand, or write callout text in a page. Both come from
  `capture/scenarios`; a hand-made image is stale the day the UI changes.
- **Must not** show anything but seeded demo data. The site is public, operator section included.
- **Must not** describe a field from memory. Take the meaning from the client's field description
  and the engine's route `description`; if they are wrong, fix them there too.
- **Must not** leave a form without a `FieldTable` row for each field it shows, including what the
  other party sees and what the field locks, posts or commits.
- **Must not** hard-code the site URL or base path. Both come from the environment.
- **Must not** use `spawnSync` in the capture stack. It blocks the reader of mongod's log pipe;
  the pipe fills and every query hangs (cost an afternoon).
- **Must not** name a function inside `page.evaluate`. The bundler wraps it in `__name()`, which
  the page does not have.
- **Must not** write an admonition title after a space (`:::note Title`). Docusaurus 3 needs
  `:::note[Title]`, or the block renders as raw text.
- **Must not** loosen the capture diff back to a share of the frame. It is an absolute 20 pixels:
  a ratio that ignored anti-aliasing also ignored a changed label, and kept a shot showing
  "Invalid Date" after the fix shipped. Re-runs are zero-diff because `shoot` pins clock times,
  "n minutes ago", job durations ("12 ms") and the sign-in greeting in the page, and `settle` stops SVG animations; pin any new moving text the same way rather than raising the bar.
- **Must not** commit shots taken with `CAPTURE_HOST_BROWSER=1`, or move the browser out of Docker.
  A host browser draws text with that system's fonts and anti-aliasing: the first CI run after
  Mac-shot images rewrote all 91 of them. Docker must be running for `yarn capture`.
- **Must not** run two captures at once. They share ports 2101/5199 and the manifest.
- **Must not** commit the platform audit shots from a `--persona operator` run. The platform log
  records every persona's sign-in, so it differs from the full run CI makes; shoot it in a full run.
- **Must not** copy a guide page into a persona folder. Write it once in `docs/_partials/` and give
  each persona page `<X who="…" />`; say persona-only facts with `{props.who === 'reseller' ? … : …}`.
  A heading that only some personas need goes in its own partial (see `catalogue-contribute.mdx`):
  the contents column is built from headings, so a heading cannot be conditional.
- **Must not** edit `docs/30-api/reference/`. Run `yarn api:ref` (reads `../neuros-engine/openapi.json`);
  a wrong summary or field is fixed in the engine route. The capture workflow regenerates it.
- **Must not** put a concrete API host in the docs. The base URL comes from `HANDBOOK_API_URL`
  (`<ApiBase />`, `$NEUROS_API` in examples); a made-up host could one day belong to someone else.
- **Must not** write a `{#id}` heading. `future.v4` turns MDX 1 heading ids off and the build fails.
- **Must not** rename or remove a page without updating `handbook.manifest.json`. `yarn check:manifest`
  fails on a missing page, and the client's coverage test fails on a route with no entry.
- **Must not** run Prettier over `docs/` — MDX tables and JSX props are laid out by hand.
