# CLAUDE.md — neuros-handbook

The Neuros Handbook. Read [`AGENTS.md`](./AGENTS.md), then [`docs/README.md`](./docs/README.md).

## What this is

A Docusaurus 3 site in three passes:
1. a glossary of every term;
2. every feature end to end;
3. a page-by-page guide for each persona: supplier (`supply`), distributor (`distribution`), reseller/buyer (`purchasing`) and the platform operator.

Its screenshots and videos are captured from the real app, so the handbook shows what the code does.

## Structure

```
docusaurus.config.ts   url/baseUrl from HANDBOOK_URL / HANDBOOK_BASE_URL (Pages now, Amplify later)
docs/00-start …        sections; the numeric prefix is the sidebar order; index.md carries the slug
docs/README.md         authoring guide (draft: not published)
src/components/        Shot (annotated screenshot + legend), FieldTable, Video, PersonaBadge
src/theme/MDXComponents.tsx  those components in every page without an import
src/data/shots.json    GENERATED by capture: shot id → file, size, numbered callouts
static/shots, static/video   GENERATED by capture
capture/stack.ts       throwaway Neuros: in-memory replica set, prepare-db (indexes first), every seed, engine, client build
capture/personas.ts    who each guide is shot as (seeded demo logins) and the real sign-in
capture/scenarios/     one file per persona: shots (path, steps, callouts) and videos (steps + captions)
capture/callouts.ts    numbered arrows drawn on the live page before the screenshot
capture/run.ts         `yarn capture [--persona x] [--only id-prefix] [--app url]`; report in capture/.out;
                       drops manifest entries (and images) whose scenario is gone
.github/workflows/capture.yml  re-shoots on app merges (repository_dispatch app-changed) and weekly; opens a PR
tools/lint-public.mjs  refuses anything unpublishable
.github/workflows/pages.yml  verify on PRs, deploy main to GitHub Pages
amplify.yml            the same build for Amplify, unused until the AWS move
```

## Must not

- **Must not** add or edit a screenshot by hand, or write callout text in a page. Both come from
  `capture/scenarios`; a hand-made image is stale the day the UI changes.
- **Must not** show anything but seeded demo data. The site is public, operator section included.
- **Must not** describe a field from memory. Take the meaning from the client's field description
  and the engine's route `description`; if they are wrong, fix them there too.
- **Must not** leave a form without a `FieldTable` row for each field it shows, including what the
  other party sees and what the field locks, posts or commits.
- **Must not** hard-code the site URL or base path. Both come from the environment.
- **Must not** use `spawnSync` in the capture stack. It blocks the reader of mongod's log pipe;
  the pipe fills and every query hangs (cost an afternoon).
- **Must not** name a function inside `page.evaluate`. The bundler wraps it in `__name()`, which
  the page does not have.
- **Must not** write an admonition title after a space (`:::note Title`). Docusaurus 3 needs
  `:::note[Title]`, or the block renders as raw text.
- **Must not** loosen the capture diff back to a share of the frame. It is an absolute 20 pixels:
  a ratio that ignored anti-aliasing also ignored a changed label, and kept a shot showing
  "Invalid Date" after the fix shipped. Re-runs are zero-diff because `shoot` pins clock times and
  "n minutes ago" in the page; pin any new moving text the same way rather than raising the bar.
- **Must not** run two captures at once. They share ports 2101/5199 and the manifest.
- **Must not** run Prettier over `docs/` — MDX tables and JSX props are laid out by hand.
