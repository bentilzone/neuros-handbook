**Webhooks** tell your own systems (an ERP, a shop, a warehouse system) when something happens in Neuros: an order accepted, an invoice issued, stock changed. Neuros sends an HTTPS POST to your endpoint for each event it carries. Each delivery is signed, and it names only the event and its record: your system reads the record with its [API client](../30-api/10-get-access.mdx). See [webhook](../01-glossary/85-integrations.mdx#webhook).

Your plan must include the Webhooks add-on. For the code your receiver needs, see [Webhooks in the API guide](../30-api/92-webhooks.mdx).

:::note[Not in your plan]
Without it, **Webhooks** shows a padlock in the sidebar. The page still opens, and endpoints set up under an earlier plan stay there with their deliveries, but nothing is sent: **Add endpoint**, **Send a test event** and **Resume** are off. Whoever manages billing can add it under **Settings → Billing**; events from then on are sent again.
:::

Once added, the **signing secret** is shown once. Copy it to where your receiver can read it; Neuros keeps it only to sign, and it cannot be shown again.

## An endpoint

<Shot id="distributor/webhooks/detail" />

- **Send a test event** sends a `webhook.test` delivery, signed like any other.
- **Rotate secret** issues a new secret, shown once. For 24 hours each delivery carries two signatures, one per secret, so your receiver can switch without missing any.
- **Pause** takes a reason; nothing is sent until you **Resume**. Deliveries already queued give up, and you can send them again afterwards.
- **Edit** changes the URL, description and events.

## Deliveries

Each event the endpoint receives is one delivery, with every attempt: when, what your receiver answered, and how long it took.

| Status | Means |
|---|---|
| Queued | Waiting to be sent |
| Delivered | Your receiver answered with a 2xx status within 10 seconds |
| Retrying | It did not; Neuros tries again after 1 minute, 5 minutes, 30 minutes, 2 hours and 12 hours |
| Gave up | Six attempts failed, or the endpoint was paused |

**Send again** on a delivered or given-up delivery sends it once more with the same event id, so a receiver that deduplicates by id handles it once.

## Common questions

**Why does a delivery hold no order details?** So nothing private travels to a URL you may later change. Your system reads the record with its API client, which also checks its scopes.

**What if my receiver is down for a day?** Deliveries retry for about 15 hours and then give up. Filter the deliveries by **Gave up** and send them again once it is back.
