The Neuros app updates without reloading because the engine tells it when something changes. Your systems can listen to the same stream instead of polling.

The stream says **what kind of record changed and which one**, never its contents. You then read the record through the API, which applies your token's permissions. So the stream cannot reveal anything your token could not already read.

## Connect

Open a WebSocket at `/v1/live` on the API host, using `wss://`. Within 10 seconds, send your access token as the first message. It goes in a message, not in the URL, so it never lands in an access log.

```js
const ws = new WebSocket(`${NEUROS_API.replace(/^http/, 'ws')}/v1/live`);
ws.onopen = () => ws.send(JSON.stringify({ type: 'auth', token: accessToken }));
ws.onmessage = (m) => {
  const msg = JSON.parse(m.data);
  if (msg.type === 'ready') console.log('listening for', msg.organizationId);
  if (msg.type === 'event') refetch(msg.event.type, msg.event.resource);
};
```

API client tokens and people's tokens both work.

## Messages

| Message | Means |
|---|---|
| `{"type":"ready","organizationId":"…"}` | Authenticated; events for this company follow |
| `{"type":"event","event":{"type":"stock.changed","resource":{"type":"…","id":"…"},"at":"…"}}` | Something changed: read it again |

Events go to the companies they concern: both sides of an account, for example. Marketplace changes go to everyone, because the marketplace is everyone's.

Some event types:

| `event.type` | When |
|---|---|
| `offer.created`, `offer.updated`, `offer.published`, `offer.withdrawn` | Your offers change |
| `marketplace.listing_changed` | An offer anyone can see changed in the marketplace |
| `price_list.changed`, `contract_price.changed`, `promotion.changed` | Your pricing changes |
| `relationship.requested`, `relationship.approved`, `relationship.updated` | An account with a customer or supplier changes |
| `stock.changed` | Stock moved |
| `stock_adjustment.changed`, `stock_transfer.changed`, `stock_count.changed` | An inventory document changes |
| `quote_request.*`, `quotation.sent`, `quotation.accepted`, `quotation.declined`, `quotation.expired` | A request for quotation or a quotation changes |
| `order.submitted`, `order.accepted`, `order.rejected`, `order.cancelled`, `order.amended`, `order.completed` | An order moves |
| `order.fulfilment_changed`, `order.payment_changed` | An order's stock or payment status changes |
| `shipment.created`, `shipment.packed`, `shipment.dispatched`, `shipment.delivered`, `shipment.failed`, `shipment.received` | A shipment moves |
| `sales_invoice.issued`, `sales_invoice.paid`, `sales_invoice.credited`, `sales_invoice.voided` | An invoice is issued or settled |
| `payment.notified`, `payment.confirmed`, `payment.rejected`, `escrow.funded`, `escrow.released`, `escrow.refunded` | A payment or escrow moves |
| `dispute.raised`, `dispute.updated`, `dispute.message`, `dispute.escalated`, `dispute.resolved`, `dispute.withdrawn` | A dispute is raised, answered, escalated or ends |
| `return.requested`, `return.authorised`, `return.rejected`, `return.received`, `return.inspected`, `return.closed` | A return moves |
| `requisition.updated`, `requisition.submitted`, `requisition.approved`, `requisition.rejected`, `requisition.ordered` | A requisition changes, waits for approval, is decided or ordered (your company only) |
| `purchase_order.updated`, `purchase_order.issued` | A purchase order to an external supplier changes or is sent (your company only) |

Trading events go to both companies once the other side can see the record; a draft's go to its owner only.

People's tokens also hear about their own notifications. These go only to that person's connections, in the company they are working in:

| `event.type` | When |
|---|---|
| `notification.created` | A notification for you arrived: read `GET /v1/notifications` |
| `notification.read` | One of yours was marked read, in another tab or app |

Platform staff can open the socket with a platform token too. They hear only their own notifications, read from `GET /v1/platform/notifications`.

Ignore types you don't use. New types appear as Neuros grows.

## Closing and reconnecting

| Close code | Means | Do |
|---|---|---|
| `4401` | No token in time, or an invalid one | Get a token and reconnect |
| `4001` | The token expired: the socket lives no longer than its token | Get a new token and reconnect |
| `4403` | A person's token with no company chosen | Choose a company first |

The server pings every 30 seconds; a connection that stops answering is dropped. After any drop, reconnect with backoff and **read what you care about again**: events sent while you were away are not replayed.
