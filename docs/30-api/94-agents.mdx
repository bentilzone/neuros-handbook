An AI agent sells for one company, the seller, to that company’s resellers in a chat. The agent platform holds the conversation; Neuros answers every fact and takes every action. The agent never computes a price, a total or a status: each answer carries `say`, a sentence or two to read to the reseller as it is.

## Before you start

You need an **agent** created by the seller under **AI agents**. Its client ID and secret are shown once. An agent is an API client that can only call the agent tools ticked for it. It gets its token like any client:

```bash
export NEUROS_API="https://<your Neuros API address>"
curl -s "$NEUROS_API/v1/oauth/token" \
  -H "Content-Type: application/json" \
  -d "{\"grant_type\":\"client_credentials\",\"client_id\":\"$AGENT_ID\",\"client_secret\":\"$AGENT_SECRET\"}"
```

Tokens last an hour; get a new one when it runs out. A person’s token is refused by every agent tool (`AGENT_ONLY`).

## Who is writing

Every tool acts for the reseller who is writing, named as `<channel>:<address>`: `whatsapp:+2348012345678`, `sms:+2348012345678` or `email:orders@shop.example`. Over REST it goes in the `X-Agent-Caller` header; over MCP it is the `caller` argument of every tool. A number without its country code takes the seller’s.

Neuros finds the seller’s account with that caller and runs the tool as that reseller, inside that account only. A reseller who buys from two sellers is a different account on each seller’s agent, and neither agent sees the other’s business.

## The tools

| Tool | REST | Does |
|---|---|---|
| `resolve_caller` | `POST /v1/agent/v1/session/resolve` | `active`, `invited`, `suspended` or `unknown`, with the reseller’s name and payment ways. Call it when a conversation starts |
| `accept_invite` | `POST /v1/agent/v1/invites/accept` | `{ "code": "482913" }`: the six-digit code from the seller’s invitation |
| `search_products` | `GET /v1/agent/v1/products?q=` | The seller’s products this reseller may see, at its own price |
| `quote_cart` | `POST /v1/agent/v1/carts/quote` | Prices the lines and holds the prices for 30 minutes; returns `quoteRef` |
| `place_order` | `POST /v1/agent/v1/orders` | `{ "quoteRef": "…" }`. Takes an `Idempotency-Key` |
| `get_order` | `GET /v1/agent/v1/orders/:ref` | Status, payment, lines and total, by order number |
| `get_payment_instructions` | `GET /v1/agent/v1/orders/:ref/payment` | Amount due, the account and the reference |
| `get_delivery` | `GET /v1/agent/v1/orders/:ref/delivery` | Shipments, dispatch and delivery |
| `get_statement` | `GET /v1/agent/v1/statement` | What the reseller owes, what is overdue, credit left |

The [reference](./reference/340-agent-tools.mdx) has every field.

## An order over REST

```bash
CALLER="whatsapp:+2348012345678"
H=(-H "Authorization: Bearer $TOKEN" -H "X-Agent-Caller: $CALLER" -H "Content-Type: application/json")

curl -s "${H[@]}" -X POST "$NEUROS_API/v1/agent/v1/session/resolve"
curl -s "${H[@]}" "$NEUROS_API/v1/agent/v1/products?q=noodles%2070g"
curl -s "${H[@]}" -X POST "$NEUROS_API/v1/agent/v1/carts/quote" \
  -d '{"lines":[{"offerId":"<offerId from search>","quantity":"30"}]}'
```

```json
{
  "quoteRef": "SO-2026-00482",
  "validUntil": "2026-10-12T10:30:00.000Z",
  "total": { "amount": "294000.00", "currency": "NGN" },
  "say": "30 Instant noodles 70g × ₦9,800.00 = ₦294,000.00. Total ₦294,000.00. These prices hold for 30 minutes. Shall I place the order?"
}
```

When the reseller says yes:

```bash
curl -s "${H[@]}" -H "Idempotency-Key: chat-7731-msg-42" -X POST "$NEUROS_API/v1/agent/v1/orders" \
  -d '{"quoteRef":"SO-2026-00482"}'
```

Use one key per “yes” in the conversation, for example the message id: a retry with the same key returns the first answer, so the reseller is never charged twice. Within 30 minutes the quoted prices stand. After that the order is refused with `409 QUOTE_EXPIRED`; quote the cart again and read the new total to the reseller.

## Over MCP

The same tools are an MCP server at `POST $NEUROS_API/v1/agent/mcp` (streamable HTTP; one JSON-RPC message per request, answered as JSON). Send the agent’s token as `Authorization: Bearer`. It answers `initialize`, `tools/list`, `tools/call` and `ping`. Each tool’s input schema is the REST input plus `caller`, and a tool’s result is its REST answer in `structuredContent` (and as text).

```json
{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": { "name": "get_order", "arguments": { "caller": "whatsapp:+2348012345678", "ref": "SO-2026-00482" } } }
```

A refusal is a tool result with `isError: true` and `{ "error": { "code", "message" } }`, so the agent can read why. Placing a quote that is already placed answers with the order, so retries are safe over MCP too.

## Errors an agent meets

| Code | Means | Say |
|---|---|---|
| `CALLER_UNKNOWN` | Not one of the seller’s customers, or an invitation not yet accepted | Offer to have the seller invite them, or ask for the code |
| `ACCOUNT_NOT_ACTIVE` | The account is suspended or ended | Ask them to contact the seller |
| `TOOL_NOT_ALLOWED` | The seller has not ticked this tool for the agent | Hand over to the seller |
| `INVITATION_CODE_WRONG`, `INVITATION_EXPIRED`, `INVITATION_LOCKED` | The code is wrong, more than 7 days old, or tried five times | Ask again, or ask the seller for a new code |
| `QUOTE_EXPIRED` | The quote passed 30 minutes and prices changed | Quote again |
| `RATE_LIMITED` | More than 600 calls a minute from this agent | Slow down |

Other errors follow [Errors](./70-errors.mdx).
